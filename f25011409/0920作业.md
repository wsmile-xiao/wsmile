## 二 自动发布方式

| 方式 | 流程与特点 | 适用情况 |
|---|---|---|
| Jenkins Pipeline | Webhook 触发检出代码、构建镜像、部署和健康检查；灵活但要维护 Jenkins 和凭据 | 自有服务器、流程需定制 |
| GitHub Actions、GitLab CI、Gitee Go | 推送或合并触发 Runner 执行测试、构建和部署；与仓库集成紧密 | 配置随代码管理 |
| Docker Compose 加脚本 | 执行 build/up，简单但通常人工触发 | 个人项目、小型服务 |
| 云平台 CI/CD | 云端构建部署，减少自建运维；需考虑费用和平台限制 | 已使用云服务的项目 |

课程 demo_1/Jenkinsfile 展示检出代码、构建 Docker Compose 镜像、停止旧容器并启动新容器、检查 Streamlit 健康端点和清理悬空镜像；DEPLOY.md 说明可由 Git Webhook 自动触发。docker-compose.yml 编排服务并持久化模型和向量数据；deploy.sh 提供人工触发的一键构建、启动和健康检查。

本项目优先选择 Jenkins + Docker Compose：Webhook 触发，Jenkins 编排流水线，Compose 构建和运行服务，健康检查验证结果。个人测试可先用 deploy.sh；自动发布前应先在测试环境验证、管理凭据并准备回滚方案。
